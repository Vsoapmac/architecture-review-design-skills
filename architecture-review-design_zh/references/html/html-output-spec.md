# HTML Output Specification (html-output-spec)

This file is the **single source of truth** for the HTML output of review reports and design documents. Both Tier 1 (Python script) and Tier 2 (handwritten by AI) must produce HTML conforming to this spec. Style and interaction code lives only in `report-shell.html`; body-structure rules follow below.

## 1. Artifact Requirements

- Single self-contained file (styles, scripts, and content all inline), opens with a double-click; file name:
  - Design: `docs/design/YYYY-MM-DD-<system>-architecture-design.html`
  - Review: `docs/review/YYYY-MM-DD-<scope>-architecture-review.html`
  - Documentation-only run (no scoring — SKILL.md Workflow A variant): `docs/architecture/YYYY-MM-DD-<scope>-architecture.html`
- The HTML **is** the architecture document. When the user asks for the `.md` source as well, keep the draft next to it with the same basename and the `.md` extension (`.md` is only preserved when `md2html.py --keep-src` is used — the generator deletes the draft otherwise, wherever it sits).
- Before rendering, the draft must pass the view gate: `python check_views.py <draft.md>` (view catalogue and cross-view consistency, per `mermaid-spec.md` §1-§8). When it fails, fix the diagrams — never lower the gate.
- Two network dependencies, both progressive enhancements that must degrade gracefully offline:
  1. Mermaid CDN (`https://cdn.jsdelivr.net/npm/mermaid@11/dist/mermaid.min.js`) — always
  2. Google Fonts Noto Sans SC — **Chinese documents on non-Apple devices only** (the shell injects it only when `data-lang="zh"`)
- No unreplaced `{curly-brace}` placeholders; metadata such as title/author/date must be real.
- **One language per document** (see §3).

## 2. Page Structure (Fixed Order)

```
<html lang="en|zh-CN" data-theme="light|dark" data-lang="en|zh">
<header id="topbar"><div class="topbar-inner"> : h1#doc-title + .meta-chips + tool buttons (#theme-btn #print-btn #collapse-all #expand-all #menu-btn)
<div id="overlay"> (drawer mask on mobile)
<div id="layout">
  <aside id="sidebar"><div class="side-inner"> : .search-wrap (#q) + ul#toc (auto-generated by JS; may be left empty in the handwritten mode)
  <main id="main"><div class="wrap"> : sequence of section.sec (see §5)
<button id="to-top"> : back-to-top button (created by the shell markup, shown after scrolling)
<div id="zoom-layer" hidden> : .zl-bar (zoom controls) + .zl-stage (fullscreen figure viewer, filled by JS)
```

The `.zoom-bar` toolbars of §8 and the contents of `#zoom-layer` are created by the shell JS — never hand-written into the body.

## 3. Language & UI Chrome (document language = menu language)

- The document language is chosen by the user **before authoring** (SKILL.md "Step 0") and covers everything: title, body, table headers, meta chips, diagram labels, figure captions, and the HTML menu.
- The language is carried on the root element: `data-lang="zh"` (or `en`) plus the matching `lang` attribute (`zh-CN` / `en`). Every menu label, tooltip and placeholder in the shell follows it (`I18N` table inside the shell; `data-i18n` / `data-i18n-aria` / `data-i18n-ph` attributes).
- Tier 1: `md2html.py --lang zh|en` writes those attributes and localizes the strings it emits itself (`aria-label` of the section toggle, the `.arch-note` caption). Without `--lang` it detects the language from the draft, and the detected language drives both the body and the chrome.
- Tier 2: set `data-lang` and `lang` by hand. If `data-lang` is missing or empty the shell detects the language from the body text — a safety net, **not** the spec path.
- Never mix: a Chinese document with English menu labels (or vice versa) is a failed artifact, even when the body is perfect.
- The shell only injects the CJK webfont for Chinese documents; English documents use the system stack.

## 4. Dual Themes and Fonts (edit report-shell.html only; the body must never hard-code colors)

- Toggle via `html[data-theme="dark|light"]`; all CSS variables are defined inside the shell.
- JS order: localStorage → if absent, prefers-color-scheme → manual 🌓 override, which is then remembered.
- In dark mode, Mermaid re-renders with theme=dark.
- Fonts: Apple-first system stack for body text; code uses `ui-monospace, "Cascadia Code", Consolas, "SF Mono", Menlo, monospace`; Chinese documents on non-Apple devices, when online, inject Noto Sans SC (400/500/700) and, on success, add the `wf-noto` class to `<body>`.
- Typography is mandatory: body text ≥14px (design value 15px), line-height ~1.75, body text at normal weight (400), headings at 600-700. Thin weight combined with light-gray small text is forbidden.

## 5. Body Components and Markdown Source Mapping (Templates Are the Contract)

Source md h2 headings are mapped by **prefix matching** once their numbering is stripped (a trailing parenthetical is ignored); changing an h2 heading in either template file (`design-doc-template.md` / `review-report-template.md`) must be synced into this table **and** into the role keys of `md2html.py`. h2 **display text keeps the source heading verbatim (number included)**; numbering is stripped only for matching and for slug/id generation. Both the English and the Chinese headings below are accepted, so the same generator serves both languages. `ROLE_KEYS` in `md2html.py` is the authoritative matcher and additionally accepts a few synonyms (`架构总览`, `决策记录`, `架构概览`, …); the tables below list the headings the templates are required to cover, not every accepted spelling.

| Source h2 prefix (design, EN) | 中文标题前缀 (design) | Produced component |
|---|---|---|
| Background & Goals | 背景与目标 | `section.sec` plain card (list items auto-badged, see §7) |
| Requirements | 需求 | `section.sec` plain card |
| Architecture Views | 架构视图 | `section.sec arch-sec`; every mermaid fence → `figure.arch` triplet (§6) |
| Module List & Responsibilities | 模块清单与职责 | `section.sec`; first table → `table.tbl` |
| Interface Definitions | 接口定义 | `section.sec`; code fence → `pre.code` |
| ADR Records | ADR 决策记录 | `section.sec adr`; each `### ADR-n: Title` → `details.adr` (collapsed by default), content continues until the next same-level heading |
| 8-Dimension Self-Check | 8 维度自检 | `section.sec selftest`; first table → `table.tbl`; status-column cells are badged whole-cell: the cell text is scanned for the markers in the order ⚠️ → ✅ → 🔴 → 🟡 → ⚪ and the whole cell becomes one chip of the first marker found (see §7 for the general badging rule) |
| Evolution Roadmap | 演进路线图 | `section.sec roadmap`; first table is placed inside `<div class="roadmap">` |

| Source h2 prefix (review, EN) | 中文标题前缀 (review) | Produced component |
|---|---|---|
| Overview | 总览 / 概览 | `section.sec overview`; score table → `table.tbl.tbl-scores` (contains the "Average" row; JS excludes it and draws the radar from the first 8 remaining rows); insert `<div class="radar-wrap">` before the table. A row whose Score cell is not a number (e.g. "not evaluated") is ignored by the radar, and **fewer than 3 numeric scores means no radar is drawn at all** — a documentation-only run should therefore drop the score table (or the whole section) rather than fill it with "not evaluated" |
| System Architecture (As-Is) | 系统架构（现状） | `section.sec arch-sec`; every mermaid fence → `figure.arch` triplet (§6) |
| Per-Dimension Details | 各维度详情 | `section.sec`; each `### Dimension n: …` → consecutive `h3.sub-h3` group boxes |
| Remediation Roadmap | 整改路线图 | `section.sec`; first table → `table.tbl` (plain card — **not** the `roadmap` role; do not rename it to "Evolution Roadmap") |
| Quick Wins | 快速见效项 | `section.sec` plain card |
| anything else (incl. the documentation-only variant's module list / interface definitions / risk list) | 其他标题 | `section.sec` plain card, generic `blocks()` rendering |

Unmatched headings always become `section.sec` (generic); h3 → `.sub-h3`; ordinary fences → `pre.code`; ordinary tables → `table.tbl`. A `### ADR-…` heading inside a section whose role is not ADR is treated as an ordinary h3 (`.sub-h3`) and must not be swallowed. Every section has this structure:

```html
<section class="sec {role}" id="{slug}">
  <h2 class="sec-title"><span>{Title}</span><button class="tgl" type="button" aria-label="Toggle section | 折叠章节" aria-expanded="true">↕</button></h2>
  <div class="sec-body">…content…</div>
</section>
```

## 6. The figure.arch Triplet (every Mermaid diagram must be written this way)

```html
<figure class="arch">
  <div class="arch-src" hidden>Mermaid source (HTML-escaped)</div>
  <div class="arch-out" role="img"></div>
  <figcaption class="arch-note">The diagram renders when online; the source is embedded below for copying.</figcaption>
</figure>
```

The `.arch-note` caption text must be in the document language (`md2html.py` emits `联网后可查看渲染图；源码已内嵌，可复制后自行渲染。` for Chinese). JS reads the textContent of `.arch-src` and calls `mermaid.render()`; when offline or on failure it adds `no-net` to `<html>`, shows `.arch-note`, and presents the source as `pre.code` inside `.arch-out`. **Never** drop in a bare `<pre class="mermaid">` (it cannot be safely re-rendered).

## 7. Badging, Link Red Lines, Images

### Automatic text badging

Badging applies in exactly two contexts: **a whole list item** and **a whole status-column cell of the self-check table**. When such text starts (leading whitespace allowed) with one of the markers below, the marker together with the following text is **wrapped as one whole entry into a single chip** (chips may wrap across lines; never wrap only the marker). Everywhere else — ordinary table cells, mid-paragraph — nothing is auto-badged:

| Marker | Class |
|---|---|
| 🔴 (severity: must-fix) | `.chip-red` |
| 🟡 | `.chip-yellow` |
| ⚪ | `.chip-gray` |
| ✅ | `.chip-ok` |
| ⚠️ | `.chip-warn` |

### Link protocol red lines (both tiers)

- Never produce executable-protocol links such as `javascript:` / `data:`; only `http`/`https`/`mailto`, `#` anchors, `/`-leading absolute paths, and relative/bare paths are allowed.
- Non-conforming links are rendered as plain text (the `<a>` is removed); no clickable script entry point may remain.

### Images

- `![alt](src)` renders as `<img class="fig-img" src alt loading="lazy">`; allowed sources: `http(s)`, relative/absolute paths, and `data:image/*` (use a data URI when the picture must live inside the self-contained file). `javascript:`, `data:text/html` and friends degrade to the alt text.
- Every image is a zoomable figure (§8); keep the alt text meaningful, since it is what offline readers and screen readers get.
- Prefer Mermaid diagrams (`.arch` triplets) for architecture content: they stay editable and theme-aware, while raster images do not.

## 8. Figure Zoom & Fullscreen (built into the shell)

Architecture diagrams are dense; the reader must be able to enlarge them. The shell attaches this to every rendered diagram, the radar chart and every `<img>` in the body — **no markup is needed in the body**:

- A `.zoom-bar` appears at the top-right corner of the figure (inside `figure.arch` for Mermaid diagrams — **not** inside `.arch-out`, whose `role="img"` makes its children presentational — and inside the figure wrapper for images/radar): `−`, current percentage, `＋`, `⟲` (reset to 100%), `⛶` (fullscreen viewer). Buttons carry localized `aria-label`s.
- Mouse/trackpad: `Ctrl/⌘ + wheel` zooms towards the pointer (after the first zoom, plain wheel keeps zooming; a single oversized wheel delta is clamped so it cannot slam to the minimum), drag pans while zoomed, double-click toggles 100% ↔ 200%.
- Touch: buttons always work; pinch and drag work where the browser delivers the gesture (`touch-action: pan-y` keeps vertical page scrolling usable); a finger left down after a pinch keeps panning.
- Zoom range is 30%–800%. Panning is clamped to the figure, so a diagram cannot be dragged out of view.
- `.arch-out` and `.radar-wrap` clip (`overflow: hidden`): an over-wide diagram is examined by zooming/panning (and `max-width:100%` keeps it fitted when JS is off) rather than by horizontally scrolling the card.
- Fullscreen viewer (`#zoom-layer`, a labelled `role="dialog" aria-modal="true"`): the figure is cloned into a dark stage sized to the viewport (an SVG fills the stage width, a raster image keeps its intrinsic size) with the section title as its label; `Esc` / `✕` / clicking the backdrop closes it and returns focus to the trigger; `+` `-` `0` adjust and reset while it is open; the click that ends a pan does not close it.
- Printing resets all transforms and hides the zoom UI, so a printed/PDF page never shows a half-zoomed figure (even if the viewer was open).
- The zoom state is per figure and survives theme changes (Mermaid re-renders reset the figure to 100%).

## 9. Accessibility and Printing

- Buttons carry aria-label; collapse buttons maintain aria-expanded; the diagram areas carry role="img" (`.arch-out` from the triplet, and `.radar-wrap`, which the generator emits with a localized `aria-label`); the zoom toolbar sits outside the `role="img"` box so its controls stay exposed to assistive tech; the fullscreen viewer is a labelled `role="dialog" aria-modal="true"` that closes on `Esc` and returns focus to its trigger.
- `@media print`: force light theme, hide #sidebar and the tool buttons, single column, avoid page breaks inside .arch/.tbl/li, chips use print-color-adjust: exact.

## 10. Additional Tier 2 (Handwritten by AI) Rules

1. Copy `report-shell.html` as the final file, **removing none of its CSS/JS/token structure**; token substitution: the title goes into `<!--T:TITLE-->`, the meta chips into `<!--T:META-->`, the whole body into `<!--T:BODY-->`; if `<!--T:EXTRA-->` is not needed, delete it wholesale.
2. Set the document language on the root element: `<html lang="zh-CN" data-theme="light" data-lang="zh">` for a Chinese document (`lang="en" data-lang="en"` for English). This drives every menu label.
3. Meta chip copy format: field name without the colon + one space + value, in the document language — `Date 2026-09-09` / `日期 2026-09-09`.
4. The `<!--T:TITLE-->` token appears at two places in the shell — `<title>` and `h1#doc-title` — and both must be replaced with the same title value.
5. `ul#toc` may stay empty (JS generates it automatically), but the title and every section must keep the §5 structural classes.
6. Write the `.arch-note` caption and the section-toggle `aria-label` in the document language (see §6, §5).
7. For the self-check list, see §11.

## 11. Output Acceptance Checklist (Both Tiers)

- [ ] Opens by double-click in a browser; no console errors
- [ ] **One language throughout**: body, headings, table headers, meta chips, diagram labels/captions and the menu chrome all in the chosen language (no English menu on a Chinese document)
- [ ] The five mandatory views are present (system context / component / layered / runtime / data flow) plus every conditional view whose trigger holds (swimlane / deployment / state machine / data model), each with a one-line "read this for" note; `python check_views.py <draft.md>` passes
- [ ] Figures zoom: `＋`/`−`/`⟲` work, `Ctrl/⌘ + wheel` and drag-pan work, `⛶` opens the fullscreen viewer, `Esc` closes it and focus returns to the trigger; images (`img.fig-img`) zoom as well; the zoom toolbar is not swallowed by the `role="img"` box
- [ ] Light/dark theme switching works and is remembered after refresh; the system preference takes effect on the first visit
- [ ] When online, Mermaid renders successfully; with the CDN blocked, a degradation notice is shown (in the document language) and the source stays copyable
- [ ] The search box filters sections and highlights hits (mark); the collapse buttons and "Collapse all / Expand all" work — the button labels match the document language
- [ ] Review report: the radar chart matches the scores of rows 1-8 of the overview table; the "Average" row does not affect the radar
- [ ] Print preview: light colors, no sidebar, no buttons, no zoom toolbars, un-zoomed figures, clean page breaks
- [ ] No `{` placeholders and no leftover `<!--T:` tokens
- [ ] ADR collapsible cards are collapsed by default and expandable; badging on list items / self-check cells (the chip contains the marker and the text) renders correctly
- [ ] Meta chips show real fields (Date/Author/Status/Scope, etc.); the title and body h2s keep the source numbering
- [ ] Both tiers' outputs are structurally consistent with each other (section cards / arch triplet / tables / badge class names per this spec); the CJK webfont is injected for Chinese documents on non-Apple devices when online and falls back gracefully offline
