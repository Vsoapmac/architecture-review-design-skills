# 架构评审报告模板

每个部分都要填充真实内容，不要保留占位文字。`{花括号}` 内的占位符必须替换或删除。
> **本文档双重职责:** ① 对话"结构化摘要"的章节大纲;② Tier 1 的 .md 源稿写作大纲(md2html.py 依赖各 h2 标题做组件映射,见 `html/html-output-spec.md` §4)。**修改 h2 标题必须同步 html-output-spec.md 的映射表。** `1. 总览(8 维度雷达)` 的评分表是雷达图数据源,`平均` 行由页面 JS 排除。

```markdown
# 架构评审报告：{项目/范围}

- **日期：** {YYYY-MM-DD}
- **范围：** {模块 / 子系统 / 全仓库}
- **评估维度：** {清单}
- **跳过维度：** {清单，附原因}

## 1. 总览（8 维度雷达）

| 维度 | 评分（0-5） | 一句话结论 |
|---|---|---|
| 1. 功能正确性 | {n} | {一句话} |
| 2. 可移植性 | {n} | {一句话} |
| 3. 可扩展性 / 可维护性 | {n} | {一句话} |
| 4. 可观测性 | {n} | {一句话} |
| 5. 可测试性 | {n} | {一句话} |
| 6. 易用性 | {n} | {一句话} |
| 7. 性能 / 可伸缩性 | {n} | {一句话} |
| 8. 安全性 | {n} | {一句话} |
| **平均** | **{avg}** | **{总体结论一句话}** |

> 评分规则：每个评分都由第 2 节的证据支撑。没有证据 → "未评估"。

## 2. 各维度详情

### 维度 {n}：{名称} — 评分 {x}/5

**证据：**
- {文件路径}:{行号} — {具体观察或代码片段}
- {文件路径}:{行号} — {具体观察或代码片段}

**发现的问题：**
- 🔴 {描述}（{位置}）
- 🟡 {描述}（{位置}）
- ⚪ {描述}（{位置}）

**亮点（可选）：**
- {做得好的地方}

---

（每个评估过的维度重复）

## 3. 整改路线图

按优先级排序（🔴 优先），每项附工作量估级。

| # | 优先级 | 问题 | 维度 | 工作量（低/中/高） | 建议修复方案 |
|---|---|---|---|---|---|
| 1 | 🔴 | {问题摘要} | {维度} | {工作量} | {一句话方案} |
| 2 | 🟡 | {问题摘要} | {维度} | {工作量} | {一句话方案} |
| 3 | ⚪ | {问题摘要} | {维度} | {工作量} | {一句话方案} |

**建议执行顺序：** {1-2-3 的推理——谁解锁谁}

## 4. 速赢（本周可做）

- {影响大、成本低的修复}
```
