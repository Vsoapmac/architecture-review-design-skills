# HTML Output Specification (html-output-spec)

This file is the **single source of truth** for the HTML output of review reports and design documents. Both Tier 1 (Python script) and Tier 2 (handwritten by AI) must produce HTML conforming to this spec. Style and interaction code lives only in `report-shell.html`; body-structure rules follow below.

## 1. Artifact Requirements

- Single self-contained file (styles, scripts, and content all inline), opens with a double-click; file name:
  - Design: `docs/design/YYYY-MM-DD-<system>-architecture-design.html`
  - Review: `docs/review/YYYY-MM-DD-<scope>-architecture-review.html`
- Two network dependencies added as progressive enhancement must degrade gracefully offline:
  1. Mermaid CDN (`https://cdn.jsdelivr.net/npm/mermaid@11/dist/mermaid.min.js`)
  2. Google Fonts Noto Sans SC (**non-Apple devices only**, injected after JS detection)
- No unreplaced `{curly-brace}` placeholders; metadata such as title/author/date must be real.

## 2. Page Structure (Fixed Order)

```
<header id="topbar"><div class="topbar-inner"> : h1#doc-title + .meta-chips + tool buttons (#theme-btn #print-btn #collapse-all #expand-all #menu-btn)
<div id="overlay"> (drawer mask on mobile)
<div id="layout">
  <aside id="sidebar"><div class="side-inner"> : .search-wrap (#q) + ul#toc (auto-generated by JS; may be left empty in the handwritten mode)
  <main id="main"><div class="wrap"> : sequence of section.sec (see §4)
footer #to-top back-to-top
```

## 3. Dual Themes and Fonts (edit report-shell.html only; the body must never hard-code colors)

- Toggle via `html[data-theme="dark|light"]`; all CSS variables are defined inside the shell.
- JS order: localStorage → if absent, prefers-color-scheme → manual 🌓 override, which is then remembered.
- In dark mode, Mermaid re-renders with theme=dark.
- Fonts: Apple-first system stack for body text; code uses `ui-monospace, "Cascadia Code", Consolas, "SF Mono", Menlo, monospace`; on non-Apple devices, when online, inject Noto Sans SC (400/500/700) and, on success, add the `wf-noto` class to `<body>` (consistent with the shell CSS selector `body.wf-noto`).
- Typography is mandatory: body text ≥14px (design value 15px), line-height ~1.75, body text at normal weight (400), headings at 600-700. Thin weight combined with light-gray small text is forbidden.

## 4. Body Components and Markdown Source Mapping (Templates Are the Contract)

Source md h2 headings are mapped by **prefix matching** once their numbering is stripped; changing an h2 heading in either template file (`design-doc-template.md` / `review-report-template.md`) must be synced into this table: h2 **display text keeps the source heading verbatim (number included)**; numbering is stripped only for matching and for slug/id generation.

| Source h2 prefix (design) | Produced component |
|---|---|
| Background & Goals | `section.sec` plain card (list items auto-badged, see §5) |
| Requirements | `section.sec` plain card |
| Architecture Overview | `section.sec arch-sec`; mermaid fence → `figure.arch` triplet |
| Module List & Responsibilities | `section.sec`; first table → `table.tbl` |
| Interface Definitions | `section.sec`; code fence → `pre.code` |
| ADR Records | `section.sec adr`; each `### ADR-n: Title` → `details.adr` (collapsed by default), content continues until the next same-level heading |
| 8-Dimension Self-Check | `section.sec selftest`; first table → `table.tbl`; status-column cells are badged whole-cell per the §5 badge table (marker present → the entire cell goes into one chip) |
| Evolution Roadmap | `section.sec roadmap`; first table is placed inside `<div class="roadmap">` |

| Source h2 prefix (review) | Produced component |
|---|---|
| Overview | `section.sec overview`; score table → `table.tbl.tbl-scores` (contains the "Average" row; JS excludes it and draws the radar from the first 8 rows); insert `<div class="radar-wrap">` before the table |
| Per-Dimension Details | `section.sec`; each `### Dimension n: …` → consecutive `h3.sub-h3` group boxes |
| Remediation Roadmap | `section.sec`; first table → `table.tbl` |
| Quick Wins | `section.sec` plain card |

Unmatched headings always become `section.sec` (generic); h3 → `.sub-h3`; ordinary fences → `pre.code`; ordinary tables → `table.tbl`. A `### ADR-…` heading inside a section whose role is not ADR is treated as an ordinary h3 (`.sub-h3`) and must not be swallowed. Every section has this structure:

```html
<section class="sec {role}" id="{slug}">
  <h2 class="sec-title"><span>{Title}</span><button class="tgl" type="button" aria-label="Toggle section" aria-expanded="true">↕</button></h2>
  <div class="sec-body">…content…</div>
</section>
```

### The figure.arch Triplet (every Mermaid diagram must be written this way)

```html
<figure class="arch">
  <div class="arch-src" hidden>Mermaid source (HTML-escaped)</div>
  <div class="arch-out" role="img"></div>
  <figcaption class="arch-note">The diagram renders when online; the source is embedded below for copying.</figcaption>
</figure>
```

JS reads the textContent of `.arch-src` and calls `mermaid.render()`; when offline or on failure it adds `no-net` to `<html>`, shows `.arch-note`, and presents the source as `pre.code` inside `.arch-out`. **Never** drop in a bare `<pre class="mermaid">` (it cannot be safely re-rendered).

## 5. Automatic Text Badging Rules

Badging applies in exactly two contexts: **a whole list item** and **a whole status-column cell of the self-check table**. When such text starts (leading whitespace allowed) with one of the markers below, the marker together with the following text is **wrapped as one whole entry into a single chip** (chips may wrap across lines; never wrap only the marker). Everywhere else — ordinary table cells, mid-paragraph — nothing is auto-badged:

| Marker | Class |
|---|---|
| 🔴 (severity: must-fix) | `.chip-red` |
| 🟡 | `.chip-yellow` |
| ⚪ | `.chip-gray` |
| ✅ | `.chip-ok` |
| ⚠️ | `.chip-warn` |

### Link Protocol Red Lines (both tiers)

- Never produce executable-protocol links such as `javascript:` / `data:`; only `http`/`https`/`mailto`, `#` anchors, `/`-leading absolute paths, and relative/bare paths are allowed.
- Non-conforming links are rendered as plain text (the `<a>` is removed); no clickable script entry point may remain.

## 6. Accessibility and Printing

- Buttons carry aria-label; collapse buttons maintain aria-expanded; figure areas carry role="img".
- `@media print`: force light theme, hide #sidebar and the tool buttons, single column, avoid page breaks inside .arch/.tbl/li, chips use print-color-adjust: exact.

## 7. Additional Tier 2 (Handwritten by AI) Rules

1. Copy `report-shell.html` as the final file, **removing none of its CSS/JS/token structure**; token substitution: the title goes into `<!--T:TITLE-->`, the meta chips into `<!--T:META-->`, the whole body into `<!--T:BODY-->`; if `<!--T:EXTRA-->` is not needed, delete it wholesale.
2. Meta chip copy format: field name without the colon + one space + value, e.g. `Date 2026-09-09`.
3. The `<!--T:TITLE-->` token appears at two places in the shell — `<title>` and `h1#doc-title` — and both must be replaced with the same title value; if `<!--T:EXTRA-->` is not needed, delete it wholesale.
4. `ul#toc` may stay empty (JS generates it automatically), but the title and every section must keep the §4 structural classes.
5. For the self-check list, see §8.

## 8. Output Acceptance Checklist (Both Tiers)

- [ ] Opens by double-click in a browser; no console errors
- [ ] Light/dark theme switching works and is remembered after refresh; the system preference takes effect on the first visit
- [ ] When online, Mermaid renders successfully; with the CDN blocked, a degradation notice is shown and the source stays copyable
- [ ] The search box filters sections and highlights hits (mark); the collapse buttons and "Collapse all / Expand all" work
- [ ] Review report: the radar chart matches the scores of rows 1-8 of the overview table; the "Average" row does not affect the radar
- [ ] Print preview: light colors, no sidebar, no buttons, clean page breaks
- [ ] No `{` placeholders and no leftover `<!--T:` tokens
- [ ] ADR collapsible cards are collapsed by default and expandable; badging on list items / self-check cells (the chip contains the marker and the text) renders correctly
- [ ] Meta chips show real fields (Date/Author/Status/Scope, etc.); the title and body h2s keep the source numbering
- [ ] Both tiers' outputs are structurally consistent with each other (section cards / arch triplet / tables / badge class names per this spec); on non-Apple devices Noto injection works when online and falls back gracefully when offline
